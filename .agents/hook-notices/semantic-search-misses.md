# 의미 검색이 한동안 답하지 않을 때 할 일

질문 훅이 기억을 찾을 때(질문마다 자동 주입), 그리고 `recall`·`remember`·기억 정리 담당이 의미 검색 서버를 부를 때, 프로그램은 서버가 떠 있으면 답을 30초까지, 꺼져 있거나 불러오는 중이면 90초까지 기다린다(기억 정리 담당은 3분). 서버를 다시 띄우는 것은 비서 쪽(질문 훅, 비서 기억 서버, 비서 서버)만 하고, run-job·업무 세션의 읽기 전용 기억 서버와 기억 정리 담당은 기다리기만 한다. 그래도 답하지 않으면(안 켜짐, 불러오는 중, 멈춤, 시간 초과, 오류) 프로그램이 그때마다 시각·기능 이름·이유를 기록 파일에 한 줄씩 남기고, 질문 훅은 아래 `ask`의 글을 붙인다. 답하지 않는 상태가 2분 넘게 이어지면 질문 훅이 `<secretary-semantic-search-server>`에 몇 분째인지, 이유별·기능별 횟수와 함께 아래 `todo`의 글을 세션마다 한 번 붙인다(서버 자체가 죽어 장애 안내가 따로 나가는 동안에는 붙이지 않는다).

"시간 초과"가 계속되면 PC가 바쁘거나 서버가 멈춘 것이니 그 이유와 횟수를 사용자에게 보고하고 서버를 다시 띄울지 묻는다. "멈춤(…사용자 확인 필요)"이면 사용자에게 다시 켤지 묻는다. 기억 정리가 이 일로 멈췄으면(정리 보고의 "정리 멈춤" 줄) 서버가 살아난 뒤 `/consolidate`를 다시 돌리자고 제안한다.

## ask

의미 검색 서버가 기다려도 답하지 않아(이유: {reason}) 이번 질문의 기억은 단어 검색으로만 찾았다. 뜻이 같고 글자가 다른 기억을 놓쳤을 수 있으니, 비서는 원래 질문에 답하기 전에 이 이유를 한 줄로 알리고 질문 하나로 먼저 묻는다: 1. 의미 검색 서버를 다시 켠다(비서가 `node scripts/semantic-search/watch-semantic-search-server.mjs --retry`를 백그라운드 명령으로 띄우고, 살아나면 원래 질문에 답한다) 2. 이 대화는 단어 검색으로만 답한다(사용자가 "단어 검색으로 답해"라고 보내면 프로그램이 이 대화에서는 기다리지도 묻지도 않는다. "의미 검색 다시 켜"라고 보내면 다시 기다린다) 3. 기타 (직접 입력). 원래 질문은 그 질문 위에 한 줄로 다시 적어 둔다. 이유가 "멈춤(…사용자 확인 필요)"이면 1번을 고를 때 `secretary.db.semantic-search-server-failures.log`(비서 폴더, DB 옆)의 마지막 실패 줄도 함께 알린다.
