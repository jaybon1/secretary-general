# 일 맡기기 (위임)

무엇을 맡길지는 AGENTS.md의 "일 맡기기"를 따른다. 이 문서는 어디에, 어떤 순서로 맡기는지다.

## 어느 상황이면 어느 파일

이 파일(목차와 공통 원칙)을 읽은 뒤, 지금 상황의 파일만 읽어 따른다. 상황이 바뀌면(예: 계획을 승인받아 업무 세션을 띄움, `[질문]`이 옴) 그 상황의 파일을 그때 읽는다. 파일은 이 스킬 폴더의 `references/` 안에 있다.

| 상황 | 읽을 파일 |
|---|---|
| 누가 할지(비서 직접·서브에이전트·업무 세션·run-job) 정할 때, 서브에이전트·run-job에 지시를 쓸 때, 비서 코드 일을 작업 사본(worktree)에 맡길 때, run-job처럼 뒤에서 도는 작업을 기다릴 때 | `references/who-and-brief.md` |
| 업무 세션에 맡길 공간을 고르거나 새로 만들 때, 계획을 보여 주고 승인받을 때, 승인받아 업무를 시작할 때(순서 1·2단계) | `references/plan-and-start.md` |
| 업무 세션이 `[질문]`으로 멈췄을 때(순서 3단계) | `references/questions.md` |
| 업무 세션이 끝났다고 알려 왔을 때: 보고 확인·대조, 회고, 제안 모음, 세션 끄기(순서 4단계) | `references/done.md` |
| "그 업무 어떻게 됐어?"처럼 맡긴 업무를 물을 때, 결과물을 아티팩트로 보여 달라고 할 때(순서 5·6단계) | `references/status-and-artifact.md` |
| 업무 세션을 띄울 때, 모니터링 알림(승인 대기·멈춤 의심·시간 끝·idle)을 받을 때, 업무 세션에 메시지를 보낼 때, 출력을 읽을 때 | `references/background-session.md` |

순서 한눈에: 1 계획 승인 → 2 시작 → 3 `[질문]` 처리 → 4 끝난 업무 마무리 → 5 업무를 물을 때 → 6 아티팩트.

## 공통 원칙

- 사용자가 결과의 말투·형식·순서 등을 고쳐 주면, 업무 세션에는 사람 이름·호칭 없이 "규칙 + 이유 한 줄"로 바꿔 전한다(업무 세션이 그대로 스킬에 적는다). 예: "제목은 20자 이내로 쓴다. 휴대폰 미리보기에서 잘리기 때문이다."
- 폰 알림은 AGENTS.md "기본" 절대로 간다. 그래서 사용자가 답하거나 직접 처리해야 할 때와 업무가 끝나 보고할 때는 답 첫 줄에 결론(무엇이 필요한지, 무엇이 끝났는지)을 쓴다. 비서가 대신 답한 질문과 단순 진행 상황은 진행 한 줄만 쓴다.
- 공간은 업무를 맡길 때만 손본다.
- 공간이 배운 것은 공간 파일(스킬·MEMORY.md)에만 둔다. 공간 파일에는 사용자 개인정보나 "사용자가 이렇게 하라고 했다" 같은 말을 쓰지 않고 규칙과 이유로만 쓴다(공간은 다른 공급자로도 돌아 그 회사 서버로 글이 나간다). 다만 사용자가 회고에서 내린 결정이 다른 공간에도 통하는 선호면 평소처럼 `remember`한다.
