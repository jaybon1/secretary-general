# 실수 막기 장치 (`mistake-guards`, 처음부터 켜짐)

비서가 규칙을 알면서도 그 순간 어기는 실수를 장치로 막고, 실수를 기록한다.

- 답변 검사(Stop 훅): 답이 영어로 쓰였거나, 결과물 경로 줄에 다른 PC 경로 줄이 빠졌거나, 대시보드 폰 주소가 있는데 결과물 경로에 누르면 열리는 링크 줄(`[주소](주소)`, 코드 블록 밖)이 없거나 그 링크 이름이 주소 그대로가 아니거나, "(추천)"을 단 선택지 바로 아래에 `근거:` 줄이 없으면 답을 한 번 되돌려 그 자리에서 고쳐 쓰게 한다(막음. 영어 답은 답 전체를 한국어로 다시 쓰게 하고, 줄만 빠졌으면 앞 답은 이미 화면에 보이니 빠진 줄만 이어 쓰게 한 뒤(추천 근거는 위치가 정해져 있어 그 질문 블록을 같은 질문 알파벳으로 다시 적게 하고, 같은 알파벳이 두 번이면 뒤의 블록으로 본다) 앞 답과 합쳐 다시 검사·기록하고 폰 알림은 앞 답의 첫 줄로 보낸다. 고쳐 쓴 답은 다시 막지 않고, 서브에이전트 안에서는 막지 않으며, 두 줄 이하의 짧은 답은 추천 근거를 보지 않는다). 결과물 폴더 경로가 문장 속에 섞였거나, 추천 근거에 확인할 수 있는 자료(파일 이름, 줄 번호, 보고, 명령)를 적고 "확인 안 함"·"안 봄"으로 넘겼거나, "자료 있음, 못 봄(<무엇>, 이유: <못 연 이유>)"에서 못 연 이유를 빠뜨렸으면 다음 질문에 알려 다음 답 맨 위에서 먼저 바로잡게 한다(알림). 경로 짝은 결과물 경로(output 아래, 보고서·노트)에만 보고, 비서 폴더와 코드·설정 파일은 보지 않는다. 검사마다 막을지·알릴지·끌지는 `this-secretary.local.json`의 `mistake-guards` 키의 `levels`로 바꾼다.
- 알림만 하는 검사가 더 있다: 추천 근거에 적은 파일·기억 번호·커밋·명령을 그 턴(과 앞 두 턴)의 도구 호출로 열었는지(출처 없이 추론만 있어도 알림), 보고를 전하며 보고의 경로를 열었는지, 지어낸 말 목록(`src/mistake-guards/invented-words.json`, `record_mistake`의 `invented_words`로 더함)의 낱말이 질문·선택지·근거 줄에 풀이 없이 나왔는지, 한 답에서 다른 질문의 답("A1이면")에 기대는 질문을 같이 물었는지.
- 걸린 것(막음·알림)은 실수 기록(`mistakes`, 찾은 쪽 '장치', 분류(group)는 검사 이름, 추천 근거 검사들은 '확인 없이 추천')에 자동으로 한 건씩 남는다. `record_mistake`는 새 분류 이름이면 비슷한 기존 분류를 보여 준다.
- 턴마다 부른 도구 이름과 검사 결과를 기억 DB(`turn_tools`)에 남긴다.
- 질문 알파벳: 이 세션의 다음 질문 알파벳을 훅이 세어 질문마다 알려 준다(새 세션은 넘어온 질문 뒤부터, compact는 이어서).
- 폴더 위치(PreToolUse 훅, 업무 세션 worker-folder-guard도): 비서 상위 폴더 바로 아래에 새 폴더·파일을 만들거나 그 `temp` 폴더에 쓰는 도구 호출을 막는다.
- 반복 작업 알림(PostToolUse 훅 `src/mistake-guards/repeat-hook.ts`, 비서·업무 세션·run-job 모두): 같은 종류 조작(같은 도구 + 같은 종류 대상: 셸 명령 앞부분, 한 폴더의 파일 읽기, 한 사이트의 페이지, 같은 브라우저 도구)이 한 턴에 10번 되풀이되면(어느 일에서나 되풀이되는 것은 세지 않는다: 셸로 파일 보기(cat·grep·sed·ls 등), 바로 적어 돌리는 코드(python -c 등), 진행 목록·에이전트 확인, 검색 결과 페이지, 같은 파일 다시·나눠 읽기·쓰기, 같은 명령 다시 돌리기, 이미지 파일 읽기(png·jpg 등, 눈으로 봐야 하는 일이라서. 이미지가 아닌 파일 읽기는 센다)) 막지 않고 "도구·스크립트로 한꺼번에 처리할 수 있는지 따져 보고, 남은 건수와 예상 시간을 계산하라"는 알림을 한 번 띄운다. 기준은 `this-secretary.local.json`의 `mistake-guards` 키의 `"repeatLimit"`(0이면 끔). 세는 기록은 임시 폴더(`%TEMP%\secretary-repeat\`)에만 두고 기억 DB에는 쓰지 않는다.
- 위임 앞뒤 대조: `node bin/delegate-check.mjs brief <TASK.md> --tag <태그>`(지시서에 빠진 결정 기억, 그 공간 스킬에서 지시서와 단어가 겹치는 규칙 줄), `node bin/delegate-check.mjs report <REPORT.md> --root <결과 폴더>`(보고의 "지웠다" 주장과 실제 파일). `delegate` 스킬의 대조 단계가 이것을 부른다.
- 실수 기록 도구: `record_mistake`, `update_mistake`, `list_mistakes`.

## 켜는 순서(설치 때 이미 켜져 있으면 건너뜀)

1. 다른 PC에서 결과물 폴더를 여는 경로가 있으면(예: `X:\ai-agent`) 사용자에게 묻고 이 비서 설정 파일 `this-secretary.local.json`(비서 폴더 맨 위, 커밋하지 않음, 예시 `this-secretary.local.example.json`)의 `paths` 키에 쓴다. 예: `"paths": { "otherPcRoot": "X:\\ai-agent" }`. 없으면 경로 짝 검사만 건너뛴다. 수준을 바꾸려면 `mistake-guards` 키에 `"mistake-guards": { "levels": { "path-pair": "off" } }`처럼 넣는다(키 안의 값은 `src/mistake-guards/mistake-guard-settings.ts` 첫 주석).
2. `features.json`의 `mistake-guards`가 `"enabled": true`인지, AGENTS.md에 아래 글이 있는지 본다.
3. 새 세션(`/clear`)부터 훅·도구가 쓰인다(비서 MCP 서버가 다시 떠야 실수 기록 도구가 보인다).

## AGENTS.md에 넣을 글

`## 답 쓰는 법` 절 첫 문단 끝의 이 문장(처음부터 들어 있다):
```
답의 형식(한국어, 경로, 질문)은 Stop 훅이 검사해서, 어기면 고치는 법과 함께 되돌려 보낸다.
```

`### 질문` 절 알파벳 줄의 이 부분(처음부터 들어 있다):
```
질문마다 알파벳(A, B…, 다음 알파벳은 훅이 알려 줌)을 붙여
```

`## 스스로 개선` 절의 "규칙으로 고칠까요?" 줄 바로 아래 줄(처음부터 들어 있다):
```
- 사용자가 비서·업무 세션·run-job·서브에이전트의 실수를 바로잡았을 때, 검수에서 보고의 틀린 점을 찾았을 때, 훅이 막은 것이 실제 실수였을 때 그 자리에서 `record_mistake`로 한 건 적는다(같은 종류는 같은 분류 이름). 같은 분류가 되풀이되면 그 규칙을 훅·검사 스크립트로 옮길지 제안한다.
```

## 끄는 순서

1. `"enabled": false`로. AGENTS.md에서 위 `record_mistake` 줄과 "답의 형식(…)은 Stop 훅이 검사해서" 문장을 빼고, 질문 알파벳 줄의 "(A, B…, 다음 알파벳은 훅이 알려 줌)" 부분을 "(A, B…, Z 다음 AA, 세션 안에서 이어 쓰고, 새 세션은 넘어온 남은 질문을 A부터 다시 붙인 다음 알파벳부터)"로 돌린다. 답 형식 세부(영어로 새지 않기, 경로 블록)는 `.agents/hook-notices/answer-format.md`에 있으니, 끈 동안은 답을 쓰기 전에 그 파일을 읽는다.
2. 새 세션부터 답변 검사·폴더 위치 훅·반복 작업 알림·다음 알파벳 알림이 멈추고 실수 기록 도구가 사라진다. 이미 남은 기록(`turn_tools`, `mistakes`)과 `this-secretary.local.json`의 `paths`·`mistake-guards` 키는 지우지 않는다. 지우려면 따로 묻는다.
