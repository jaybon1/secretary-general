# 세션 넘기기

단계가 끝날 때마다 한 줄로 진행을 남긴다. 아래 세션 도구(`create_session`, `get_session`, `list_triggers`, `archive_session` 등)는 Claude 데스크톱 앱이나 Remote Control로 연 세션에만 있다. 도구가 없으면 여기서 멈추고, 새 세션은 사용자가 직접 열면 된다고 알린다(새 세션의 첫 질문에 상황판이 붙는다).

1. **확인:** 이 세션에 남은 것을 모아 짧게 보여 준다. 묻지 않고 다음 단계로 간다.
   - 남은 질문: 새 세션 상황판에 자동으로 넘어간다(기호는 A부터 다시 붙는다).
   - 돌고 있는 업무(`list_tasks`의 running): 새 세션 상황판의 "돌고 있는 업무"로 넘어가고, 새 세션이 감시를 다시 띄운다(이 세션의 감시는 보관 때 함께 꺼지고, 다른 프로세스의 감시는 살아 있어도 새 세션 것으로 치지 않는다).
   - 이 세션에 걸린 예약(`list_triggers`에서 persistent_session_id가 이 세션인 것. 이 세션 id는 `get_session`을 id 없이 불러 얻는다): 아래 2단계대로 옮긴다.
2. **새 세션:** `get_session`(id 없이)으로 이 세션 id를 얻고, `create_session`(environment는 생략해 이 세션과 같은 곳, 제목 "비서")으로 연다. 끝난 일·진행 상황·다음 행동은 새 세션이 이 세션 대화로 상황판을 고쳐 써서 알게 되므로, prompt에는 상황판이 담지 못하는 것만 적는다.
   - 첫 줄은 "[이전 비서 세션에서 넘긴 맥락]"(이 말로 시작하면 첫 질문 훅이 상황판을 넣지 않는다).
   - 옛 세션 id 두 가지: 원격 세션 id(`get_session`의 `session_...`, 보관용)와 로컬 세션 id(이 세션 대화 기록 파일 이름, `search_log`에 나오는 이 세션 번호를 `node src/cli.ts` 없이 알 수 있게 `~/.claude*/projects/<비서폴더>/`에서 가장 최근에 고친 .jsonl 이름).
   - 옮길 예약(있으면): 이름·시각(UTC)·메시지 전문과 옛 trigger_id. 다른 세션에 예약을 거는 것은 막혀 있어 새 세션이 사용자 지시로 `send_later`를 걸고 옛 것을 `delete_trigger`한다. 사용자에게 "새 세션에서 '예약 옮겨'라고 해 달라"고 알린다.
   - 기억 정리는 넘기기에서 하지 않는다. 상황판은 대화 기록으로 만들고, 정리는 새 세션에서 평소처럼 대화가 쌓이면 제안한다.
   - 마지막 줄: "session-handoff 스킬의 '새 세션에서 잠 깨기'를 따르라."
3. **턴 끝내기:** 사용자에게 무엇을 넘겼는지 한 줄씩 알리고 "새 세션이 이 세션을 보관합니다"라고 적은 뒤 바로 턴을 끝낸다. 이 세션은 스스로 보관하지 않는다(보관하면 턴이 도중에 끊겨 마지막 대화가 기록에 남지 않는다). 새 세션이 깨어나지 못하면 이 세션이 그대로 남는다.

## 새 세션에서 잠 깨기

"[이전 비서 세션에서 넘긴 맥락]"으로 시작하는 첫 메시지를 받은 새 세션이 한다.
1. `get_session(옛 원격 세션 id)`로 옛 세션이 일을 멈췄는지 본다(status_bucket이 working이 아니면 멈춘 것). 아직 일하는 중이면 `Monitor`로 30초쯤 기다렸다 다시 보고, 5분이 지나도 멈추지 않으면 보관하지 말고 사용자에게 알린다.
2. 멈췄으면 `archive_session(옛 원격 세션 id)`.
3. `node src/cli.ts session-handoff-wake <옛 로컬 세션 id>`를 돌린다. 옛 세션의 마지막 대화까지 기록에 넣고 상황판을 고쳐 써서 출력한다(약 30초).
4. 답은 출력된 상황판을 읽고 `> 이어서: …` 한 줄만 쓴다. 갱신이 실패했으면 그 사실과 원인을 한 줄 더 적는다.
