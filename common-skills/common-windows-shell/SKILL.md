# Windows 셸 주의사항

여기 적은 것은 대부분 오류 없이 결과만 틀린다(엉뚱한 폴더, 깨진 한글, 잘린 인자). 그래서 명령을 돌린 뒤 결과(파일 위치, 글자, 받은 인자)를 직접 확인한다.

## PowerShell 5.1 (Windows PowerShell, `powershell.exe`)

- 한글이 든 .ps1은 UTF-8 BOM을 붙여 저장하거나, 한글을 .ps1 안에 직접 쓰지 않고 인자로 넘긴다.
  이유: 5.1은 BOM 없는 UTF-8 .ps1을 ANSI(코드 페이지)로 읽어 한글 문자열이 깨진다.
- 파일을 쓸 때는 `Set-Content`·`Out-File`에 `-Encoding utf8`을 붙인다.
  이유: 5.1의 기본 인코딩이 한글을 깨뜨린다.
- 스크립트에서 인자(`$Target`)와 내부 변수(`$target`)를 대소문자만 다르게 쓰지 않는다.
  이유: PowerShell 변수는 대소문자를 가리지 않아 인자가 덮어써지고, 복사가 종료 0으로 끝나도 엉뚱한 폴더에 들어간다.
- 배열 인자(입력 파일 여럿 등)를 넘길 때 `powershell -File x.ps1 -Inputs "a","b"`로 부르지 않는다. `& 'x.ps1' -Inputs 'a','b'` 꼴을 임시 .ps1에 담아 그 파일을 실행한다.
  이유: `-File`은 배열을 넘기지 못해 두 경로가 한 문자열로 붙고, 받는 스크립트는 없는 파일 하나를 받는다.
- `-File`로 부를 때 인자 안의 큰따옴표는 지워진다. 공백이 든 경로를 한 인자 안에 넣을 때는 `\"C:\a b\c.mp4\"`처럼 쓴다. 여러 줄이거나 따옴표가 많은 글(지시, 메시지)은 인자로 넘기지 말고 UTF-8 파일에 써서 파일 경로로 넘긴다(받는 스크립트에 `-PromptFile` 같은 파일 인자가 있으면 그것을 쓴다).
  이유: 5.1이 `-File` 인자 안의 큰따옴표를 지우거나 글을 공백에서 쪼갠다.
- 명령을 잇는 `&&`·`||`, 삼항 연산자 `?:`, `??`는 5.1에 없다. `A; if ($?) { B }`처럼 쓴다.
  이유: 5.1에서는 구문 오류로 그 줄 전체가 돌지 않는다.

## Git Bash (Windows의 bash)

- `/`로 시작하는 인자(예: `/c`, 원격 경로 `/home/...`, 다른 프로그램의 `/옵션`)를 넘길 때는 `MSYS_NO_PATHCONV=1`을 앞에 붙인다.
  이유: Git Bash가 `/`로 시작하는 인자를 Windows 경로(`C:/Program Files/Git/...`)로 바꿔 넘긴다.
- 한국시간은 `TZ=KST-9 date`나 PowerShell `Get-Date`로 확인한다.
  이유: Git Bash에는 시간대 자료가 없어 `TZ=Asia/Seoul date`가 조용히 UTC를 낸다.

## Python으로 Windows 경로·명령 줄을 만들 때

- Windows 경로는 raw 문자열(`r"E:\..."`)이나 `pathlib.Path`로 쓴다. 백슬래시 뒤 글자·숫자는 이스케이프로 바뀐다: `\0`·`\t`는 NUL·탭, `\261101`처럼 백슬래시 뒤 숫자는 8진수 문자.
  이유: `E:\<폴더>\0공통\...\tts`의 `\0`·`\t`가 NUL·탭으로 바뀌어 복사가 '경로에 잘못된 문자'로 실패했고, 경로가 조용히 다른 글자로 바뀌어 엉뚱한 폴더를 찾은 적도 있다.
- 명령 줄은 문자열 하나로 이어 붙이지 말고 인자 목록(`subprocess.run([...])`)으로 넘긴다. 파일이 많으면 명령 줄에 싣지 말고 목록 파일 하나에 써서 넘긴다.
  이유: 공백·따옴표가 든 경로가 쪼개지고, 명령 줄이 Windows 길이 한도를 넘으면 `WinError 206`으로 실패한다.
- 글을 읽고 쓸 때는 `encoding="utf-8"`(BOM이 있을 수 있는 파일은 `utf-8-sig`)을 적는다.
  이유: Windows의 Python 기본 인코딩은 코드 페이지라 한글이 깨지거나 BOM이 글 앞에 남는다.
